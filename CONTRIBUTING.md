# Contributing

Thank you for helping improve this independent CCAR-F study resource.

## What to contribute

- Corrections to technical explanations or exam-guide alignment.
- Practical examples in .NET, Python, AWS, Azure or other relevant stacks.
- Clear architecture diagrams and decision tables.
- New original scenario-based practice questions with answer rationales.
- Updates to version-sensitive Claude Code, Anthropic API or MCP implementation details, with authoritative sources.

## Contribution rules

1. Preserve the terminology and framing of the supplied exam blueprint when editing exam-focused material.
2. Clearly label any additional interpretation or current-product implementation note.
3. Cite official documentation for claims about current product behavior.
4. Do not claim community questions are actual exam questions.
5. Do not submit confidential, recalled, leaked or unauthorized live exam content.
6. Do not copy third-party material unless its license permits redistribution; include attribution and license details where required.
7. Keep examples runnable or label them as illustrative/pseudocode.
8. Explain why a proposed answer is correct and why plausible alternatives are weaker.

## Pull request process

1. Open an issue for substantial changes before starting work.
2. Make focused changes in the relevant domain or practice-question file.
3. Include sources and the date checked for version-sensitive claims.
4. Check Markdown links, tables and code fences.
5. Describe the problem, change and validation performed in the pull request.

## Suggested issue labels

- `technical-correction`
- `exam-preparation`
- `new-example`
- `documentation`
- `needs-verification`
